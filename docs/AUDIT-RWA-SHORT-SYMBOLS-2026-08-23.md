# گزارش مختصر AUDIT — شناسه کوتاه دارایی‌های واقعی

**تاریخ:** ۱۴۰۵/۰۶/۰۱ (2026-08-23)

**دامنه:** املاک، خودرو و هویت مشترک دارایی واقعی (`assets.symbol`)

## نتیجه

- الگوی قبلی طولانی بود: `RE-AHZ-KPE-APT-0001` برای ملک و `VEH-0001` برای خودرو.
- ستون `assets.symbol` در کل سامانه یکتا است؛ بنابراین دو شمارنده جدا نمی‌توانند هم‌زمان `001` داشته باشند.
- الگوی جدید یک دنباله مشترک برای همه دارایی‌های واقعی است: `001`، `002`، … .
- مقدار استاندارد در پایگاه داده با رقم ASCII ذخیره می‌شود (`001`) و در رابط فارسی با رقم فارسی نمایش داده می‌شود (`۰۰۱`). این تفکیک، جست‌وجو و یکپارچگی فنی را پایدار نگه می‌دارد.
- شهر، محله، نوع ملک، برند و مدل از شناسه حذف نشده‌اند؛ این اطلاعات همچنان در فیلدها و جداول ساخت‌یافته خود نگهداری می‌شوند و دیگر داخل Symbol تکرار نمی‌شوند.

## کنترل‌های یکپارچگی

1. تولید شناسه ملک و خودرو از یک تابع و یک توالی مشترک انجام می‌شود.
2. هنگام ثبت نهایی، ردیف مشترک کلاس RWA قفل می‌شود تا ثبت هم‌زمان دو دارایی شناسه تکراری نسازد.
3. قید یکتای `assets.symbol` همچنان لایه نهایی محافظت است.
4. Migration شماره `0008` شناسه دارایی‌های موجود را بدون تغییر مبلغ، Posting، Lot، Snapshot یا محاسبات مالی بازشماری می‌کند.
5. برای هر تغییر قدیم/جدید یک رویداد `MIGRATE_RWA_SHORT_SYMBOL` در Audit Log ثبت می‌شود؛ سابقه قبلی دفترکل و Audit بازنویسی نمی‌شود.

## ریسک باقیمانده

شناسه‌های ترتیبی قابل حدس‌اند، اما مجوز دسترسی بر اساس UUID و مالک کاربر کنترل می‌شود و Symbol کلید مجوز نیست؛ بنابراین شناسه کوتاه نباید در هیچ API به‌عنوان کنترل دسترسی استفاده شود.

## استقرار و تأیید

```bash
npm run db:migrate
npm run typecheck
npm run test
```

آزمون‌ها پوشش می‌دهند: `001 → ۰۰۱`، توالی مشترک ملک/خودرو، عبور امن از شناسه اشغال‌شده، مهاجرت Symbolهای قدیمی و ثبت before/after در Audit Log.
