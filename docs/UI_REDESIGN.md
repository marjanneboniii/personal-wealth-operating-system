# بازطراحی تجربه کاربری PWOS — «Calm Ledger»

این سند حاصل یک **بازطراحی سیستمی** است، نه پچ صفحه‌به‌صفحه: ابتدا اپلیکیشن موجود Audit شد، سپس Design System، معماری اطلاعات و همه مسیرهای اصلی از نو طراحی شدند. هسته مالی (حسابداری دوطرفه، دفترکل تغییرناپذیر، FIFO، قواعد تراز) **عمداً دست‌نخورده** باقی مانده است؛ این بازطراحی فقط لایه تجربه و ارائه است.

---

## ۱) یافته‌های Audit اپلیکیشن قبلی

| مشکل | اثر |
|---|---|
| رنگ هویت برند **سبز** بود (`#0e9f6e`) | نقض قاعده بنیادین محصولات مالی: سبز/قرمز فقط باید یعنی «جهت پول» |
| تم/or سایه/دو‌آرایه رنگی و گرادیان در همه‌جا | اغتشاش بصری، حس «قالب آماده» |
| ۹ مقصد تخت در سایدبار + آیکون‌های Emoji ناهمگون | عدم مقیاس‌پذیری، ظاهر غیرحرفه‌ای |
| داشبورد = ~۱۲ کارت تایل‌مانند («Card Soup») | هیرارشی نبود؛ کاربر در ۵ ثانیه چیزی نمی‌فهمید |
| **صفحه تراکنش‌ها وجود نداشت** (فقط دفترکل حسابداری) | مهم‌ترین گردش‌کار روزانه کاربر غایب بود |
| ارزش خالص فقط یک کارت کوچک در داشبورد بود | بدون بازه، بدون دلیل تغییر |
| بودجه‌ها در DB بود اما هیچ UI نداشتند | قابلیت مرده |
| Empty state = متن خاکستری کوچک؛ بدون اسکلت لودینگ، بدون صفحه خطا/آفلاین/۴۰۴ | عدم اعتماد در لحظات حساس |
| بدون میان‌بُر صفحه‌کلید، بدون Command Center، بدون Bottom Navigation استاندارد | محصول «شبیه دسکتاپ داخل مرورگر» |
| خطاها و وضعیت‌ها فقط با رنگ منتقل می‌شدند | نقض دسترس‌پذیری |
| PWA: مانیفست بود اما بدون رجیستر SW، بدون صفحه آفلاین، بدون safe-area | نصب‌پذیری ناقص |

## ۲) Design System

### توکن‌ها (`src/app/globals.css`)
- **سطوح**: `--bg #f7f7f5`، `--surface`، `--sunken`، `--surface-elev` + نسخه Dark.
- **برند — iris عمیق** `#4c4edb` (دارک `#8d8ff2`): هرگز برای مثبت/منفی مالی استفاده نمی‌شود.
- **معنایی فقط برای معنا**: `--positive` = ورود/رشد پول، `--negative` = خروج/کاهش، `--warning`، `--info`. وضعیت‌ها **هرگز فقط با رنگ** نیستند — فلش ↑/↓، آیکون و متن همراه است.
- **شعاع**: ۸/۱۲/۱۶/۲۰ (کارت‌ها ۱۶، نه ۲۲). **سایه‌ها**: سه پلکان کوچک و فقط برای ارتفاع.
- **اعداد شهروند درجه‌یک**: `.num` (tabular-nums) و `.display-num` برای ارقام بزرگ؛ چینش مالی همیشه راست‌چین الـLTR.

### اجزا (`src/components/ui/Card.tsx`)
`Card` (فقط برای گروه معنایی واقعی)، `Section` («واحد پیش‌فرض محتوا» — عنوانِ به شکل **سؤال مالی**)، `PageHeader`، `Money`، `Delta` (فلش + مقدار + درصد + مرجع)، `Pct`، `Stat`، `Metric` (KPI بدون کادر)، `Progress/meter`، `EmptyState` (چه چیزی کم است + چرا مهم است + CTA)، `Skeleton`، `Alert` (۵ تُن با آیکون).

### اجزای ساختاری
`Icon` (۴۵+ گلیف خطی یکدست ۲۴px — بدون هیچ Emoji)، `Sheet` (Bottom Sheet موبایل / دیالوگ دسکتاپ، Esc + قفل اسکرول)، `CommandPalette` (⌘K)، `SubmitButton` (useFormStatus).

### نمودارها (`src/components/charts/`)
`AreaChart` (با کنترل بازه، گرید و مقدار خوانا بدون هاور)، `NetWorthChart` (رسم ارزش‌خالص تحت مالکیت URL)، `Donut` (با مرکزِ مجموعِ زنده و لیجن'd کیبورد-پذیر)، `BarsChart` (درآمد/هزینه با خوانش مستقیم). همه SVG سبک، بدون وابستگی.

```
HUMAN FINANCE LAYER     ثروت ▸ نمای کلی
                        پول ▸ تراکنش‌ها · حساب‌ها · جریان نقدی · دفترکل

                        برنامه‌ریزی ▸ پیش‌بینی · بودجه‌ها · اهداف · بدهی‌ها · اقساط
```

منبع واحد حقیقت: `src/lib/nav.ts` (برچسب + **سؤال مالی** + کلیدواژه ⌘K برای هر مقصد).
- **دسکتاپ**: سایدبار گروه‌بندی‌شده و **جمع‌شونده** (tooltip در حالت آیکونی، ماندگار در localStorage).
- **موبایل**: Bottom Navigation فقط با ۵ شکاف — خانه، دارایی‌ها، تراکنش‌ها، برنامه‌ریزی، بیشتر (More Sheet کامل).
- **مرکز فرمان**: `⌘K`/`Ctrl+K` در همه‌جا؛ ناوبری + اقدام سریع؛ جستجوی فارسی/انگلیسی با نرمال‌سازی حروف.
- **میان‌بُرها**: `/` = فوکوس جستجو در تراکنش‌ها.

## ۴) هر صفحه، یک سؤال

| مسیر | سؤالِ طراحی |
|---|---|
| `/` | وضعیت مالی من چگونه است؟ |
| `/transactions` | چه اتفاقی برای پول افتاده است؟ |
| `/accounts` | پول من در کدام حساب‌هاست؟ |
| `/cash-flow` | پول از کجا می‌آید و کجا می‌رود؟ |
| `/portfolio` · `/crypto` | چه چیزهایی در اختیار دارم؟ |
| `/net-worth` | آیا ثروتمندتر می‌شوم؟ چرا؟ |
| `/planning` · `/budgets` · `/goals` · `/debts` · `/installments` | قدم بعدی چیست؟ آیا در چارچوبم؟ |
| `/ledger` | دقیقاً چه در سوابق حسابداری ثبت شده؟ |
| `/audit` | آیا به این اعداد می‌توانم اعتماد کنم؟ |
| `/reports` · `/market-data` · `/import` · `/settings` | تصویر کامل / پیکربندی |

### نمای کلی — ترتیب بخش‌ها (قانون ۵ ثانیه)
قهرمان (ارزش خالص + Δ نسبت به آخرین اسنپ‌شات + معادل تومانی + ثبت سریع) → نوار ساختار (دارایی/بدهی/نقدشونده با Divider نه کارت) → روند → ترکیب → جریان نقد ماه → «نیازمند توجه» → فعالیت اخیر.

### تراکنش‌ها — سریع‌ترین گردش‌کار
نوار چسبان فیلتر (جستجو ۳۰۰ms debounce، نوع، بازه، حساب، بررسی‌نشده) با **URL state** (اشتراک‌پذیر، back مرورگر کار می‌کند) → ردیف‌های بازشونده: ردیف‌های حسابداری + فریز تاریخی نرخ + لینک قسط + وضعیت بازبینی + ابطال با سند معکوس → انتخاب گروهی: خروجی CSV + تأیید دسته‌جمعی.

### ارزش خالص — صفحه پرچم‌دار
عدد بزرگ + Δ مطلق و درصدی؛ بازه‌های `1M/3M/6M/YTD/1Y/ALL` در URL؛ ترکیب ثروت در ۴ سطل انسانی؛ **Change Attribution** (پس‌انداز خالص + کاهش بدهی + عملکرد بازار/بازارزش‌گذاری) که جمعش دقیقاً برابر Δ است + نوار شاخص‌های سلامت (بازده تعدیل‌شده، افت از سقف، تمرکز).

### دفترکل — ثبت حسابداری
نوار گواهی (بررسی تراز زنده + قواعد)، تراز آزمایشی با ستون بدهکار/بستانکار + سطر جمع، دفتر روزنامه با اسناد بازشونده (بازکردن کامل ردیف‌ها، فریز FX، لینک قسط، ابطال).

### حسابرسی — موتور اعتماد (`src/features/integrity/service.ts`)
۷ آزمون زنده روی DB: تراز دفترکل، کامل‌بودن ردیف‌ها، سازگاری FIFO، پیوند قسط↔سند، پوشش قیمت ۳۰روزه، تکراری‌ها، پوشش بازبینی. هر کدام: وضعیت/شرح انسانی/تعداد متاثر/نمونه/شدت/اقدام حل + بنر **Financial Integrity** و دنباله audit_log.

## ۵) گردش‌کار بازبینی (جدید، افزایشی و سازگار)
جدول `entry_reviews(entry_id, reviewed_at)`: ثبت‌های **دستی خودکار تأیید می‌شوند**؛ رکوردهای **درون‌ریزی تا تأیید انسان «بررسی‌نشده»** می‌مانند (نشان هشدار، فیلتر اختصاصی، شمارنده در نمای کلی، آزمون حسابرسی، لینک از پایان درون‌ریزی). جدول در backup/restore هم لحاظ شده است.

## ۶) وضعیت‌ها و اعتماد
- **اسکلت** به‌جای اسپینر (`loading.tsx` در ریشه و تراکنش‌ها/ارزش‌خالص) که چیدمان بالفعل را حدس می‌زند.
- **خطای انسانی**: پیام فارسی صادقانه («نمی‌توانیم اطلاعات مالی را بخوانیم… داده‌های شما امن‌اند»)، دکمه «تلاش دوباره»، مسیر تنظیمات، کد پیگیری. تشخیص خطای دیتابیس.
- **Empty states** همیشه سه‌بخشی: چه چیزی کم است / چرا مهم است / اقدام بعدی.
- **آفلاین**: بنر اتصال زنده + صفحه `/offline` + ناوبری network-first با کش صفحات (SW) — استراتژی آفلاین «فقط‌خواندنی».

## ۷) PWA و دسترس‌پذیری
مانیفست standalone + شورت‌کات‌های بومی (ثبت هزینه/تراکنش‌ها/ارزش خالص)، آیکون SVG بهینه، `theme-color` دوحالته، `viewport-fit: cover` و `env(safe-area-inset-bottom)`، رجیستر SW (فقط production)، کش فونت CDN.
کیبورد: skip-link، `aria-current`، `aria-pressed/expanded`، نقش‌های dialog/status، `focus-visible` رینگ برند، حداقل ۴۰px (۴۴px لمسی) هدف، `prefers-reduced-motion` محترم‌شده، چاپ (print) برای گزارش ماهانه.

## ۸) چه چیزی عمداً تغییر نکرد
قواعد دامنه (`assertBalanced`، بدون ستون موجودی، اصلاح فقط با سند معکوس، FIFO، عدم ثبت سود تحقق‌نیافته در دفترکل)، ساختار دیتابیس به‌جز افزودن `entry_reviews`، اقدام‌های سرور موجود، و امنیت (اعتبارسنجی zod سمت سرور، فریز FX اتمیک با سند).
