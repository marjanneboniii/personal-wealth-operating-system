# اتصال پیامک آیفون به توازن

پیاده‌سازی مستقل؛ هیچ سورس یا پکیجی از آرا اجرا یا نصب نشده است.

## رفتار

راه‌اندازی مالی اولیه پیش از صفحات مالی و اتصال پیامک لازم است. صفحه‌های تنظیمات حساب، تغییر رمز و مدیریت برای انجام کارهای هویتی و مدیریتی استثنا هستند. اتوماسیون دریافت پیام در Shortcuts روی آیفون به تنظیم یک‌باره کاربر نیاز دارد؛ PWA به مخزن SMS دسترسی نمی‌گیرد و حساب Apple Developer لازم نیست.

در `/transactions/import` کاربر رضایت ارسال پیام‌های بانکی را اعلام و کلید اختصاصی دستگاه ایجاد می‌کند. کلید تصادفی ۲۵۶ بیتی فقط همان بار نمایش داده و فقط هش آن ذخیره می‌شود. حداکثر پنج اتصال فعال؛ قابل لغو و فقط دارای مجوز ارسال پیام است. کلید حسابداری، دسترسی خواندن صندوق یا ورود به حساب نمی‌دهد. نام فرستنده ارسالی ادعای دستگاه است و احراز هویت بانک نیست.

پیام در صندوق مشترک همان کاربر ذخیره می‌شود؛ بازکردن وب یا PWA صندوق یکسانی دارد. دریافت هیچ سند مالی ایجاد نمی‌کند. نوع، حساب، دسته/منبع، مبلغ، تاریخ، نرخ و عدم احتساب در افتتاحیه باید تأیید شوند. از مسیر حسابداری موجود استفاده می‌شود. پس از ثبت یا رد، متن خام و فرستنده حذف می‌شوند و اثرانگشت برای جلوگیری از تکرار باقی می‌ماند.

افتتاحیه بر اساس روز ثبت شده و زمان دقیق مبنای هر حساب در مدل فعلی وجود ندارد. بنابراین فیلتر زمان فعال‌سازی جای تطبیق با موجودی افتتاحیه را نمی‌گیرد؛ تأیید جداگانه کاربر لازم است. پیام دارای تاریخ قدیمی‌تر از روز اتصال در منطقه تهران یا زمان ارسال پیش از اتصال رد می‌شود. زمان sentAt زمان ثبت رویداد در Shortcuts است، نه زمان احرازشده توسط بانک.

## آدرس نسخه آنلاین

دامنه تأییدشده کاربر: `https://tavazon.vercel.app`؛ آدرس دریافت: `https://tavazon.vercel.app/api/bank-messages`؛ صفحه تنظیم اتصال: `https://tavazon.vercel.app/transactions/import`. migration شماره 0034 در پروژه Supabase توازن اعمال و در تاریخچه Drizzle ثبت شد؛ RLS هر دو جدول فعال و دسترسی anon و authenticated بسته بودن آن تأیید شد. تنظیم دامنه و کلید رمزگذاری محلی انجام شده است. انتشار کد و تنظیم متغیرهای Production در Vercel هنوز تأیید نشده است. وجود آدرس به‌تنهایی به معنی فعال‌بودن endpoint نیست.

## تنظیم محیط

- migration افزایشی `drizzle/0034_iphone_sms_inbox.sql` با مسیر موجود `npm run db:migrate` اعمال شود. هیچ DDL هنگام درخواست اجرا نمی‌شود.
- `NEXT_PUBLIC_SITE_URL` آدرس عمومی HTTPS قابل دسترسی از آیفون باشد. کلید یا اطلاعات بانکی نباید در URL قرار گیرد.
- `FIELD_ENCRYPTION_KEY` کلید ثابت تصادفی ۳۲ بایتی در قالب base64 باشد؛ فقط سرور. کلید رمزگذاری موجود را تعویض نکنید. بدون آن اتصال جدید ساخته نمی‌شود. پشتیبان کلید برای بازیابی متن‌های در انتظار ضروری است.
- نرخ‌سنج موجود برای endpoint استفاده می‌شود. برای چند نمونه سرور، `REDIS_URL` لازم است؛ در محیط محلی شمارنده حافظه‌ای است.
- هر دو جدول RLS فعال دارند؛ PUBLIC، anon و authenticated مجوزی ندارند. دسترسی فقط از سرور مورد اعتماد با نقش مناسب PostgreSQL است. هیچ policy عمومی یا تابع SECURITY DEFINER اضافه نشده است.

## تنظیم Shortcuts

۱. Automation → Message؛ انتخاب بانک/عبارت تراکنش و Run Immediately. برای هر الگوی بانک تنظیم جداگانه. شرایط و نمایش گزینه‌ها بسته به نسخه iOS تفاوت دارد.
۲. متن پیام از Shortcut Input (Text/Content)، فیلتر پیام رمز و تأیید با If.
۳. Current Date → Format Date با ISO 8601 شامل offset. مقدار زمان یک بار برای رویداد تولید شود.
۴. Get Contents of URL → آدرس `/api/bank-messages` روی دامنه توازن؛ POST، JSON؛ Header `Authorization: Bearer <کلید اختصاصی>` و `Content-Type: application/json`.
۵. کلید JSON `message` متغیر متن واقعی پیام، `sentAt` متغیر زمان قالب‌بندی‌شده و `sender` اختیاری. متغیرها نباید به‌صورت متن ثابت تایپ شوند.
۶. بررسی پاسخ `ok`؛ در خطا Show Notification. اجرای واقعی، حالت گوشی قفل، بانک با فرستنده متنی، مجوز شبکه و رفتار نسخه iOS روی دستگاه آزموده شود.

منابع: [اجرای خودکار Message](https://support.apple.com/en-ke/guide/shortcuts/apd602971e63/9.0/ios/26)، [ارسال درخواست API](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios).

## قرارداد دریافت

```json
{
  "message": "بانک ملت برداشت: 250000 تومان",
  "sender": "بانک ملت",
  "sentAt": "2026-09-17T12:00:00+03:30"
}
```

پاسخ 202 `{ "ok": true, "duplicate": false }` یعنی دریافت موفق، نه ثبت مالی. ارسال دوباره همان متن/فرستنده/زمان در همان حساب duplicate است. پیام یکسان با زمان متفاوت رویداد دیگری است و تطبیق دفترکل هنگام تأیید همچنان انجام می‌شود. در retry زمان رویداد را دوباره تولید نکنید.

401 کلید نامعتبر/لغوشده؛ 403 راه‌اندازی ناقص؛ 400 ورودی نامعتبر؛ 413 بدنه بیش از ۳۲ کیلوبایت؛ 415 قالب غیر JSON؛ 422 پیام رمز یا پیش از فعال‌سازی؛ 409 صندوق پر؛ 429 محدودیت نرخ؛ 503 خطای سرویس. هر پیام حداکثر ۸۰۰۰ نویسه و صندوق حداکثر ۱۰۰ پیام باز دارد. پیام در حال ثبت قابل رد نیست؛ پس از اختلال فرایند، تلاش مجدد بعد از پنج دقیقه ممکن است و idempotency از سند تکراری جلوگیری می‌کند.

## حدود نسخه

اتوماسیون آماده و نصب‌شده روی آیفون کاربر ادعا نشده است. این نسخه صف و retry آفلاین روی دستگاه ندارد؛ اینترنت هنگام ارسال لازم است و خطا باید در Shortcuts به کاربر اعلام شود. نسخه‌های iOS و الگوهای بانک‌ها به آزمون واقعی نیاز دارند. هیچ دسترسی به Chrome، MetaMask، Rabby، OTP بانک یا انتقال پول اضافه نشده است.

آزمون یکپارچه در دیتابیس حافظه‌ای: راه‌اندازی، مجوز کاربر، رمزگذاری، RLS/مجوز جداول، رد ورودی حجیم/رمز/قدیمی، دریافت بدون سند، تکرار، صندوق جداگانه، تأیید افتتاحیه و دسته، ثبت یک‌باره، حذف متن و لغو اتصال.
