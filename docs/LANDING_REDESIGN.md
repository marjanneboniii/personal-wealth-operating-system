# بازطراحی Landing Page «تراز» — Product-grade Landing

این سند خلاصه‌ای از فرایند بازطراحی صفحه معرفی (Landing) است: از Audit ساختار قبلی تا
معماری اطلاعات، Design System و پیاده‌سازی. هسته مالی (حسابداری دوطرفه، دفترکل، FIFO،
قواعد تراز) و تمام ماژول‌های اپلیکیشن **دست‌نخورده** باقی مانده‌اند؛ تغییرات فقط در لایه
معرفی محصول است.

---

## ۱) یافته‌های Audit نسخه قبلی

| مشکل | اثر |
|---|---|
| Hero متن‌محور بدون نمایش واقعی محصول (اعداد «—» و نوارهای Placeholder) | کاربر در ۵ ثانیه نمی‌فهمید محصول چه شکلی است |
| ساختار تخت: امکانات → درباره → اعتماد (Explain × ۳) | بدون مسیر Show → Explain → Prove → Convert |
| Feature Listing به‌جای Outcome | کاربر نتیجه استفاده را نمی‌دید |
| بدون Problem/Solution Story | چرایی محصول (نه فقط چیستی) منتقل نمی‌شد |
| بدون How It Works، Persona، Final CTA | حلقه تبدیل ناقص بود |
| Header بدون ناوبری بخش‌ها؛ Footer بدون آکاردئون موبایل | تجربه موبایل عمومی |
| بدون JSON-LD و canonical | SEO پایه ناقص |

## ۲) معماری اطلاعات جدید

```
Header (سبک، کم‌ارتفاع، چسبان)
├─ Hero + پیش‌نمایش واقعی داشبورد محصول        → Attention
├─ مسئله: «ندیدن تصویر کامل» (پراکندگی → تراز) → Problem
├─ راه‌حل: جریان ۸ مرحله‌ای تا تحلیل/تصمیم      → Solution
├─ معماری محصول: «همه چیز به هم متصل است»       → Architecture
├─ امکانات Outcome-محور (۶ قابلیت واقعی)        → Outcomes
├─ از داده تا فهم (پیش‌نمایش ماه جاری)          → Understanding
├─ برای چه کسی؟ (۳ Persona)                     → Personalization
├─ نحوه کار (۰۱ ثبت تا ۰۴ تصمیم)                → How it works
├─ اعتماد (کنترل داده، شفافیت، قابل پیگیری، حریم) → Trust
├─ چرا تراز ساخته شد؟ (Product Story کوتاه)     → Story
└─ CTA پایانی: «تصویر واقعی ثروت‌تان را ببینید»  → Conversion
Footer (۴ ستون؛ موبایل: آکاردئون `<details>` بدون JS)
```

## ۳) Design System — Quiet Premium

- **رنگ**: همان توکن‌های «Calm Ledger» (کاغذ `#F7F7F5`، آیریس `#4C4EDB`، مثبت/منفی معنایی).
  آیریس فقط در نقاط تعامل؛ سبز/قرمز فقط جهت پول.
- **اعداد شهروند درجه‌یک**: Tabular numerals، `dir="ltr"` ایزوله، عدد مهم‌تر از Label.
- **کاهش کارت**: ردیف‌های Divider محور، Flow، Diagram، Dashboard Preview و متر به‌جای
  کارت‌های تکراری.
- **Motion محدود**: `Reveal` (fade + slide ظریف با IntersectionObserver)، Count-up اعداد،
  رسم خط نمودار؛ همه با `prefers-reduced-motion` غیرفعال و بدون JS (محتوا از ابتدا در
  DOM است).
- **نوع**: Vazirmatn خودمیزبان (Regular/Bold برای بالای لبه Preload شده).

## ۴) پیش‌نمایش‌های محصول (Mock واقعی، بدون داده واقعی)

همه اعداد نمونه و آزمایشی هستند و در خود پیش‌نمایش برچسب «داده آزمایشی» دارند:

1. **Hero Dashboard**: ارزش خالص `$184,250 ↑ 8.4%`، دارایی‌ها `$231,500`، بدهی‌ها
   `$47,250`، نقدشونده `$61,400`، درآمد `+$12,400`، هزینه `−$5,280`، سرمایه‌گذاری
   `−$2,500`، جریان نقدی `+$7,120` + Sparkline + بودجه (۶۸٪) + ۴ تراکنش ساختاریافته.
2. **ماه جاری (Data → Understanding)**: درآمد/هزینه/سرمایه‌گذاری/پس‌انداز + ارزش خالص ↑3.8%.
3. **Inline Proof ها** در بخش امکانات (متر بودجه، چیپ‌های تراکنش، بررسی یکپارچگی).

## ۵) راست‌گویی با محصول (Trust)

- فقط قابلیت‌های واقعاً پیاده‌شده معرفی شده‌اند (دفترکل، حسابرسی، بودجه، سبد دارایی…).
- هیچ ادعای امنیتی ساخته نشده؛ بخش اعتماد به همان چیزهایی اشاره دارد که در مخزن پیاده است
  (وابستگی سوابق به حساب، پشتیبان‌گیری/بازیابی، اجرای صریح برنامه‌ها، قابل ردیابی تا دفترکل،
  بدون تله‌متری).
- پیش‌نمایش‌ها صریحاً «نمونه» هستند و داده واقعی کاربر را نمایش نمی‌دهند.

## ۶) Responsive / PWA

- موبایل‌اول: Breakpointهای ۴۸۰/۶۴۰/۹۰۰/۹۶۰؛ هدر ۳۲۰px هم تمیز می‌ماند (CTA کوتاه‌شونده).
- Hero در موبایل: لوگو ← Eyebrow ← H1 ← متن ← [شروع مدیریت مالی] ← [مشاهده نحوه کار] ←
  Dashboard (عمودی، بدون Overflow).
- منوی موبایل: `<details>` بومی (بدون JS کار می‌کند) + بستن با Esc/کلیک بیرون.
- Footer موبایل: آکاردئون `<details>` بومی.
- PWA: `safe-area-inset` در هدر/فوتر، `scroll-margin` برای انکرها، `viewport-fit: cover`،
  فونت Preload، بدون وابستگی JS برای محتوای اصلی، CLS ~ صفر (اعداد نهایی در HTML اولیه).
